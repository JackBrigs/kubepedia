# skills/

Скиллы — это **поверхность продукта**, а не служебные файлы Claude Code: они описывают, как
задавать базе вопросы и какие правила действуют при ответе. Поэтому канонический текст лежит
здесь, в репозитории, и живёт под ревью вместе с базой и инструментами.

| Скилл | Назначение |
|---|---|
| [`kubepedia`](kubepedia/SKILL.md) | ответ на вопрос по Kubernetes/Kubespray из базы: симптом или сырой вывод → разбор, версии по тегам, отчёт об апгрейде, проверка после апгрейда |

## Как это разложено

Claude Code читает скиллы из `.claude/skills/<имя>/SKILL.md`, а каталог `.claude/` в этом проекте
не коммитится (служебные файлы). Поэтому:

- **канонический файл** — `skills/<имя>/SKILL.md` (в git, правится здесь);
- **рабочая копия** — `.claude/skills/<имя>/SKILL.md` — симлинк на канонический.

Развернуть на новой машине (или восстановить, если симлинк потерялся):

```bash
mkdir -p .claude/skills/kubepedia
ln -sf ../../../skills/kubepedia/SKILL.md .claude/skills/kubepedia/SKILL.md
```

Если окружение не подхватывает скилл по симлинку — положить обычную копию тем же путём
(`cp skills/kubepedia/SKILL.md .claude/skills/kubepedia/SKILL.md`) и не забывать пересинхронизировать
после правок.

## Правило

Правки вносятся в `skills/`, а не в `.claude/`. Скилл — часть контракта проекта наравне со
`standards/`: он задаёт, что считается корректным ответом (версия как фильтр, факты вместо отсылок,
прогоны Kubespray в терминах AWX, внутренние идентификаторы документов наружу не показываются).
